1. Visão Geral do Projeto

O DIO Explorer é um sistema integrado ao IBM Bob que transforma o catálogo de trilhas da DIO (Digital Innovation One) em uma experiência interativa de IA. O usuário conversa naturalmente ou digita slash commands e recebe respostas formatadas em Markdown sobre trilhas, desafios, certificados, promoções e lives.

Propósito Tornar o catálogo de 30 trilhas da DIO acessível via linguagem natural e comandos estruturados, integrando a plataforma de IA IBM Bob com dados reais de cursos, XP, badges, promoções e eventos ao vivo.

O que o projeto entrega

FuncionalidadeDescrição
Exploração de TrilhasLista, busca e detalhes de 30 trilhas com tecnologia, nível, módulos e XP
Recomendação InteligenteSugere trilhas por nível do usuário (iniciante/intermediário/avançado) e área de interesse
Desafios de CódigoGera desafios criativos por tecnologia e nível com exemplos reais
CertificadosEmite certificados fictícios comemorativos com dados reais da trilha

Agenda de LivesMostra próximas aulas ao vivo agrupadas por data
Ranking e EstatísticasXP ranking e métricas gerais do catálogo

3. Slash Commands do Bob (.bob/commands)

Estes são os prompts de sistema registrados no Bob. Quando o usuário digita um slash command, o Bob injeta o prompt correspondente como contexto e executa a instrução.

/trilha <tecnologia> .bob/commands/trilha.md

O que faz: Lê trilhas_dio.json, localiza a trilha por nome ou tecnologia (busca parcial e case-insensitive) e exibe um plano de estudos completo em Markdown.

Comportamento de fallback: Se nenhuma trilha for encontrada, lista todas as tecnologias disponíveis em tabela.

  • Gera lista de módulos progressivos baseada em numero_modulos
  • Exibe badges disponíveis, lives agendadas e promoção ativa
  • Termina com CTA para /desafio e /certificado

Exemplo de uso:

/trilha Python   /trilha aws   /trilha Machine Learning
/desafio <tecnologia> <nível> .bob/commands/desafio.md

O que faz: Gera um desafio de código criativo e único com contexto de cenário real, requisitos funcionais, restrições técnicas, exemplos de entrada/saída e critérios de avaliação.

Tabela de complexidade por nível:

NívelComplexidade esperada
Básico / InicianteLógica simples, strings/arrays, estruturas de controle
IntermediárioOOP, APIs, estruturas de dados, padrões de projeto básicos
AvançadoAlgoritmos O(n log n)+, concorrência, otimização de memória

Exemplo de uso:

/desafio Python Intermediário   /desafio TypeScript Avançado
/certificado <nome> <trilha> .bob/commands/certificado.md

O que faz: Gera um certificado comemorativo em Markdown com dados reais da trilha (lidos do JSON), data atual, código único de 12 caracteres e assinaturas fictícias.

  • Lê o JSON antes de gerar — se encontrar a trilha, usa dados reais; caso contrário, cria valores coerentes
  • Inclui tabela de informações, lista de badges e declaração oficial
  • Data gerada automaticamente no formato DD/MM/AAAA

Exemplo de uso:

/certificado João Silva Python   /certificado Maria AWS Developer

5. MCP Server (DIO_EXPLORER/MCP)

O coração técnico do projeto. Implementa o protocolo Model Context Protocol (MCP) expondo 12 tools que o IBM Bob usa automaticamente para responder perguntas sobre as trilhas.

Modos de Transporte

ModoVariávelQuando usar
stdio (padrão)MCP_TRANSPORT=stdioUso local com Bob / Claude Desktop. O Bob spawna o processo diretamente.
HTTPMCP_TRANSPORT=httpAcesso remoto, APIs REST, integração com outros sistemas via HTTPS.

Instalação e Build

cd DIO_EXPLORER/MCP
npm install
npm run build

Registro no Bob (mcp.json)

{
  "mcpServers": {
    "dio-explorer": {
      "command": "node",
      "args": ["C:/PROJETOS/PROJETO_FINAL_BOB/DIO_EXPLORER/MCP/build/index.js"]
    }
  }
}

Modo HTTP com API Key

# Iniciar o servidor
MCP_TRANSPORT=http PORT=3100 API_KEY=minha-chave-secreta node build/index.js

# Chamada via curl
curl -X POST http://localhost:3100/mcp \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer minha-chave-secreta" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": { "name": "list_trilhas", "arguments": {} }
  }'

9. Dicas e Boas Práticas

Desenvolvimento

Tip 1 — Separação de módulos O código em SRC/ e MCP/src/ é intencionalmente duplicado. Isso permite testar a lógica isolada sem o protocolo MCP. Em projetos maiores, extraia para um pacote compartilhado (@dio-explorer/core).
Tip 2 — Cache do JSON O arquivo data.ts usa um módulo-level cache (let _cache) que persiste durante toda a vida do processo. É eficiente para stdio, mas em HTTP stateless pode ser um problema se o JSON for atualizado — adicione lógica de invalidação com TTL se necessário.
Tip 3 — Zod para validação Todas as tools MCP usam z.object({...}) do Zod para validar entrada. Isso garante que o Bob (e outros clientes MCP) recebam erros descritivos se passarem tipos errados, sem precisar de try/catch manual nos parâmetros.
Tip 4 — Tool genérica como fallback A tool executar_slash_command aceita qualquer string e roteia internamente. Isso é útil para clientes que preferem passar o comando completo como texto em vez de escolher a tool específica.

Prompts

Tip 5 — Argumento hint O frontmatter argument-hint nos arquivos .md instrui o Bob a sugerir o formato correto de argumentos ao autocompletar. Use sempre para comandos com parâmetros.
Tip 6 — Referências a arquivos no prompt Quando o prompt diz "leia o arquivo X", o Bob tenta carregar e injetar o conteúdo automaticamente. Mantenha os caminhos relativos ao workspace raiz para evitar problemas de resolução.

MCP e Segurança

Aviso — API Key em produção Nunca suba o arquivo .env com API_KEY preenchida para o repositório. Use o .env.example como template e adicione .env ao .gitignore. O Bob suporta ${env:NOME_DA_VAR} no mcp.json para carregar secrets do ambiente.
Aviso — CORS em produção O padrão CORS_ORIGINS=* é adequado apenas para desenvolvimento. Em produção, defina origens específicas: CORS_ORIGINS=https://meusite.com,https://app.meusite.com

10. Insights para Profissionais

Insight 1 — O padrão "dados + prompt + ferramenta" Este projeto demonstra a arquitetura fundamental de aplicações de IA: um arquivo JSON como fonte de verdade, prompts que instruem o modelo a lê-lo, e tools MCP que fazem a ponte entre o modelo e os dados. Esse padrão escala para bases de dados reais (PostgreSQL, MongoDB) substituindo apenas a camada data.ts.
Insight 2 — MCP como API universal de IA O protocolo MCP (Model Context Protocol) é o "HTTP das ferramentas de IA". Uma vez que você publica um MCP Server, qualquer cliente compatível (Bob, Claude Desktop, VS Code, etc.) pode usar suas tools sem reescrever integração. É a camada de padronização que o ecossistema de IA precisava.
Insight 3 — Slash commands como UX de IA Enquanto linguagem natural é poderosa, slash commands oferecem previsibilidade: o usuário sabe exatamente o que vai receber. A combinação dos dois (natural + estruturado) é a melhor UX para assistentes de IA produtivos.
Insight 4 — Template de saída como contrato Definir o formato de saída no prompt (como nos certificados e planos de estudo) é equivalente a um contrato de API: o modelo sabe exatamente o que produzir, e o cliente sabe o que esperar. Isso é crucial para integração com sistemas downstream.
Insight 5 — O .bob/commands/ como "microserviços de prompt" Cada arquivo .md em .bob/commands/ é um prompt isolado, versionável, testável e reutilizável. Tratar prompts como código — com versionamento no Git, revisão em PR e documentação — é uma prática de MLOps para projetos com IA.
Insight 6 — TypeScript + Zod = MCP Server robusto A combinação de TypeScript (tipagem estática) + Zod (validação em runtime) + MCP SDK cria um servidor de tools que é ao mesmo tempo seguro, documentado e extensível. Os tipos TypeScript em data.ts também servem como documentação viva do schema JSON.

11. FAQ

Como adicionar uma nova trilha ao catálogo?

Edite DIO_EXPLORER/DATA/trilhas_dio.json seguindo o schema existente. Não é necessário recompilar nada — o JSON é lido em tempo de execução. O cache em memória se reinicia junto com o processo.

Como criar um novo slash command?

1. Crie um arquivo .bob/commands/meucomando.md com frontmatter description e argument-hint.
2. Adicione o handler em SRC/router.ts e MCP/src/tools.ts.
3. Registre no COMMANDS/slash-commands.json.

Como expor o MCP Server via HTTPS?

Use um proxy reverso (Nginx, Caddy ou Traefik) na frente da porta 3100. Veja o exemplo Nginx no MCP/README.md. Depois registre no Bob com a URL HTTPS no mcp.json.

Os certificados são válidos de verdade?

Não — são certificados fictícios e comemorativos criados para fins de aprendizado. Para certificados oficiais DIO, acesse a plataforma em dio.me.

Qual versão do Node.js é necessária?

Node.js ≥ 18 e npm ≥ 9. O projeto usa ES Modules ("type": "module" no package.json) e imports dinâmicos, que requerem Node 18+.

O que é o tool executar_slash_command?

É uma tool "coringa" que aceita qualquer slash command como string (ex: /recomendar iniciante web) e roteia internamente para o handler correto. Útil para clientes que preferem passar comandos como texto em vez de escolher a tool específica.
